## The idea

A conditional type selects a type based on assignability. infer introduces a type variable within the matched pattern, useful for extracting function results, array elements and other nested relationships.

## Why it matters

A conditional over a naked type parameter distributes over unions. Wrap each side in a tuple to test the union as a whole. never represents no possibilities and disappears from unions. Prefer built-in ReturnType, Parameters and Awaited when they already describe your intent; recursive custom types can slow the editor and obscure errors.

## A practical example

```ts
type ElementOf<T> = T extends readonly (infer U)[] ? U : never;
type Item = ElementOf<string[]>; // string

type IsString<T> = T extends string ? "yes" : "no";
type Distributed = IsString<string | number>; // "yes" | "no"
type Whole<T> = [T] extends [string] ? "yes" : "no";
type Together = Whole<string | number>; // "no"

type Load = () => Promise<{ id: string }>;
type Loaded = Awaited<ReturnType<Load>>; // { id: string }
```

## Common mistakes

infer does not inspect runtime values. A complicated type that passes compilation can still sit over an unvalidated payload. Avoid clever conditional types where a simple named union is clearer.

## Try it yourself

Write a type extracting the error variant from a result union using Extract. Predict IsString&lt;never&gt; before checking the compiler: it is never because there are no union members to distribute over.

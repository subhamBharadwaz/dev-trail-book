## The idea

Rendering computes what the UI should look like. React then commits necessary changes. Keys help match siblings between renders, so state follows a logical item rather than its position in a list.

## Why it matters

Use a stable identifier from your data. Index keys become risky when you insert, remove, or reorder items; random keys force fresh identities on every render. A key is meaningful within its sibling list and is not passed as a normal component prop.

## A practical example

```tsx
function Notes({ notes }) {
  return (
    <ul>
      {notes.map((note) => (
        <NoteRow key={note.id} note={note} />
      ))}
    </ul>
  );
}
// Preserve note.id when editing or reordering a note.
```

## Common mistakes

Memoization does not repair broken identity or impure rendering. Correctness comes before reducing renders.

## Try it yourself

Build an editable list and insert an item at the start. Compare stable IDs with index keys and observe which input state moves.

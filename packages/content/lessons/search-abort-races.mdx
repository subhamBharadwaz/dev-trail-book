## The idea

The earlier search exercise added AbortController to an Effect and then displayed “The operation was aborted” during normal typing. That cancellation is expected cleanup, not a failure to show to the user. Keep genuine request failures visible while ignoring work that belongs to an obsolete query.

## Why it matters

A timer limits request frequency; abort cancels supported work; an active flag prevents an obsolete continuation from writing state. Guard finally too: an old request must not clear the loading state of a newer request. This example assumes /api/users implements server-side name filtering and returns an array.

## A practical example

```tsx
useEffect(() => {
  const controller = new AbortController();
  let active = true;
  const timer = setTimeout(async () => {
    setLoading(true);
    setError("");
    try {
      const response = await fetch(
        `/api/users?q=${encodeURIComponent(search)}`,
        { signal: controller.signal },
      );
      if (!response.ok) throw new Error("Search failed");
      const data = await response.json();
      if (active) setUsers(data);
    } catch (error) {
      if (active && !controller.signal.aborted) {
        setError(error instanceof Error ? error.message : "Search failed");
      }
    } finally {
      if (active) setLoading(false);
    }
  }, 300);
  return () => {
    active = false;
    clearTimeout(timer);
    controller.abort();
  };
}, [search]);
```

## Common mistakes

Do not paste a Markdown-formatted link into the fetch URL. The endpoint must be an actual URL string. Cancellation should not erase a genuine error from the currently active request.

## Try it yourself

Test rapid typing, clearing the input, slow responses, a 500 response, and unmounting. For a fetch-all API, fetch once and filter locally instead.

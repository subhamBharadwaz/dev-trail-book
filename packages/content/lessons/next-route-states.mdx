## The idea

An App Router segment can define a page and supporting files such as layout.tsx, loading.tsx, error.tsx, and not-found.tsx. Layouts express shared structure; loading UI provides a pending boundary; error and not-found UI communicate different outcomes.

## Why it matters

Expected validation failures should be represented in the relevant form or action state. Unexpected exceptions belong in an error boundary with a useful recovery path. A missing record is not automatically a server outage, and a pending request is not an empty successful result.

## A practical example

```tsx
// app/journal/[id]/page.tsx
import { notFound } from "next/navigation";
export default async function EntryPage({ params }) {
  const { id } = await params;
  const entry = await getEntryForCurrentUser(id);
  if (!entry) notFound();
  return (
    <article>
      <h1>{entry.title}</h1>
    </article>
  );
}
// Add segment loading.tsx, error.tsx, and not-found.tsx as needed.
```

## Common mistakes

A single spinner cannot communicate every request state. Keep pending, missing, empty, and failed outcomes distinct.

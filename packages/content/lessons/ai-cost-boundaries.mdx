## The idea

An AI feature has input/context limits, output limits, provider latency, transport latency, and application overhead. Log the measurements needed to understand behavior without storing sensitive prompts or credentials unnecessarily.

## Why it matters

Track time to first useful output separately from total duration. Usage and cost estimates require the relevant provider’s current accounting and prices; this note deliberately uses variables rather than claiming fixed rates. Decide what data may leave the application and how long logs should retain it.

## A practical example

```ts
const measurement = {
  requestId: crypto.randomUUID(),
  startedAt: performance.now(),
  firstChunkMs: null,
  totalMs: null,
  inputTokens: null,
  outputTokens: null,
  status: "connecting",
};
// When supplied by your integration, attach actual usage and timing.
// Keep credentials and private prompt text out of routine telemetry.
```

## Common mistakes

Do not claim an exact token count or cost when the integration did not return enough information to calculate it.

## Context, latency and cost reasoning

A context window bounds the combined request and generated output according to the model protocol. Reserve output space before adding history or retrieved text; do not blindly truncate away the current question or required instructions. Select relevant context, bound tool-result size and summarize deliberately. Track first-output latency separately from total duration. Record actual provider usage when returned; cost estimates require the exact model, current rates, token categories and relevant caching rules. Keep unreported usage unknown. Redact customer data, credentials and prompt text from routine logs, with deliberate retention and access controls.

## The idea

Type annotations check a value but can broaden its apparent type. satisfies checks assignability while retaining the expression’s useful inferred type. as const prevents literal widening and gives object properties and array positions readonly types.

## Why it matters

Use satisfies for route maps, variant dictionaries and configuration objects. It is not a cast or a runtime validator. as const is also compile-time only: aliases can still refer to mutable runtime objects. Template literal types combine string unions, making useful event and route contracts without runtime string validation.

## A practical example

```ts
type Route = { path: string; private: boolean };
const routes = {
  notes: { path: "/notes", private: true },
  login: { path: "/login", private: false },
} as const satisfies Record<string, Route>;

type RouteName = keyof typeof routes; // "notes" | "login"
type Event = `${RouteName}:opened`;
const event: Event = "notes:opened";
const path = routes.notes.path; // "/notes"
```

## Common mistakes

Do not replace validation of dynamic configuration with satisfies. An assertion can hide an invalid object; satisfies reports a mismatch. Excess-property checking is strongest on fresh literals and is not exact-object validation.

## Try it yourself

Add a route with private: "yes" and inspect the error. Compare the type of path using an explicit Record annotation, satisfies alone and as const satisfies.

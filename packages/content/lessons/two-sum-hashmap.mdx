## The idea

For each value x, the matching value is target - x. A map can remember values already visited and their indices, so you can test the complement before storing the current value. Under the usual hash-map assumptions, this gives expected linear time and linear extra space.

## Why it matters

The invariant is that the map contains only earlier indices. Checking first prevents an element from matching itself. State the contract for no solution and duplicates before coding; the plan explicitly records Two Sum as pending.

## A practical example

```js
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const needed = target - nums[i];
    if (seen.has(needed)) return [seen.get(needed), i];
    seen.set(nums[i], i);
  }
  return null;
}
console.log(twoSum([3, 3], 6)); // [0, 1]
```

## Common mistakes

Do not test an index with if (seen.get(value)): index zero is falsy and can hide a valid match.

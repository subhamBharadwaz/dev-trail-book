## The idea

A join combines rows according to a relationship condition. INNER JOIN returns matches; LEFT JOIN also preserves unmatched rows from its left side. A one-to-many join can produce several output rows per parent, which affects counts, pagination, and aggregate results.

## Why it matters

Before writing a join, state the cardinality and the shape the caller needs. For parent-level pagination, joining children too early can change which parents fit on a page. Keep authorization predicates in the query and use parameter binding for external values.

## A practical example

```sql
SELECT e.id, e.title, COUNT(t.id) AS tag_count
FROM entries e
LEFT JOIN entry_tags et ON et.entry_id = e.id
LEFT JOIN tags t ON t.id = et.tag_id
WHERE e.owner_id = $1
GROUP BY e.id, e.title
ORDER BY e.id;
-- COUNT(t.id) counts matched tags, not the preserved null row.
```

## Common mistakes

Do not fix duplicate-looking rows by adding DISTINCT without understanding the relationship. It may hide the wrong query shape.

## Try it yourself

Create one entry with two tags and one entry with none. Predict the joined rows and both count expressions before running the query.

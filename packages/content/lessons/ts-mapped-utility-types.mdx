## The idea

Mapped types iterate over a key union. Utility types such as Pick, Omit, Partial, Required, Readonly and Record express common transformations without duplicating every field.

## Why it matters

Pick selects an explicit allowlist; Omit removes named keys but includes future added keys. Partial makes properties optional, not recursively partial or runtime validated. Readonly prevents assignment through that type; it neither freezes the object nor makes nested objects immutable. Key remapping uses an as clause and can combine template literal types with property names.

## A practical example

```ts
type Note = { id: string; title: string; ownerId: string };
type RenameNote = Pick<Note, "title">;
type NotePatch = Partial<RenameNote>;
type Labels<T> = {
  [K in keyof T as K extends string ? `on${Capitalize<K>}` : never]:
    (value: T[K]) => void;
};
type NoteEvents = Labels<RenameNote>;
const handlers: NoteEvents = { onTitle: value => console.log(value) };
```

## Common mistakes

Do not use Omit&lt;User, "password"&gt; as your only public-data policy: a future secret field could leak. Build and validate a deliberate DTO allowlist. Avoid deep recursive utility types without a concrete requirement.

## Try it yourself

Derive a public user DTO with Pick. Add a private token to the source type and confirm the DTO does not change. Then write a mapped type that makes every field readonly.

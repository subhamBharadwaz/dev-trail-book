## The idea

An index can reduce work for compatible lookups or ordering, at a cost in storage and write maintenance. A transaction groups operations under the database’s consistency and isolation rules. An N+1 query pattern performs one read for parents and another per parent, multiplying round trips.

## Why it matters

Use EXPLAIN to understand a query plan and realistic data to measure improvement. Use transactions for invariants such as creating an entry and its initial tags together. Batching or joining related reads can remove N+1 work; transaction boundaries alone do not remove it.

## A practical example

```sql
CREATE INDEX entries_owner_created_id
ON entries (owner_id, created_at DESC, id DESC);

BEGIN;
INSERT INTO entries (id, owner_id, title) VALUES ($1, $2, $3);
INSERT INTO entry_tags (entry_id, tag_id) VALUES ($1, $4);
COMMIT;
-- Roll back the transaction if either required write fails.
```

## Common mistakes

Do not run EXPLAIN ANALYZE on a production mutation as though it were read-only. Use a safe environment and understand execution behavior.

## Try it yourself

Compare loading tags one entry at a time with one batched query. Measure query count and inspect the relevant index plan.

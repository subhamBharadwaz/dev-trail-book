## The idea

A slow page can spend time on network requests, server work, JavaScript transfer and execution, rendering, layout, or expensive interactions. These are different bottlenecks. A profiler and a network trace help identify which one currently limits the experience.

## Why it matters

Reproduce the problem under meaningful conditions, record a baseline, make one bounded change, and measure again. Memoization helps only when it avoids enough expensive repeated work. Code splitting helps initial loading when it defers work the first task does not need.

## A practical example

```js
const start = performance.now();
const visible = topics.filter(matchesQuery);
const duration = performance.now() - start;
console.log({ duration, count: visible.length });
// Pair a local measurement with a full interaction trace.
// A tiny filtering duration is not evidence to add useMemo everywhere.
```

## Common mistakes

Do not claim a measured improvement without recording comparable before and after conditions.

## Try it yourself

Profile a filterable page and record its slowest user-visible interaction. Implement one justified fix and compare traces.

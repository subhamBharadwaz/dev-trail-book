## The idea

A controlled input receives its current value from React state and reports edits through a change handler. An uncontrolled input keeps its current value in the DOM. Choose deliberately rather than switching ownership during the component lifetime.

## Why it matters

Initialize a controlled text value to an empty string, not undefined. Keep labels, validation messages, pending state, and submission feedback connected. Browser validation improves usability but cannot replace validation at the server boundary.

## A practical example

```tsx
const [name, setName] = useState("");
return (
  <form
    onSubmit={(event) => {
      event.preventDefault();
      if (!name.trim()) return;
      console.log(name.trim());
    }}
  >
    <label htmlFor="name">Name</label>
    <input
      id="name"
      value={name}
      onChange={(event) => setName(event.target.value)}
      required
    />
    <button type="submit">Continue</button>
  </form>
);
```

## Common mistakes

Updating a related preview in an Effect is usually unnecessary when it can be derived from the current input state.

## The idea

Lexical scope determines where a binding is visible. Function declarations are initialized early in their scope; var bindings begin as undefined. let and const bindings exist in their scope but cannot be accessed before initialization: that interval is the temporal dead zone.

## Why it matters

The useful interview explanation is not that JavaScript physically moves source lines. Explain how bindings are created and initialized, then track execution. Block scope, function scope, and module scope determine which value a name refers to.

## A practical example

```js
console.log(total); // undefined
var total = 3;

function read() {
  // Reading label here would throw ReferenceError.
  const label = "ready";
  return label;
}
console.log(read());
```

## Common mistakes

Do not confuse an unavailable binding with a binding whose value is undefined. They produce different behavior.

## Try it yourself

Compare var and let inside a loop with delayed callbacks. Explain which bindings each callback retains.

## The idea

For closed numeric intervals, sorting by start puts potential overlaps next to the current merged interval. If the next start is at most the current end, extend the current end; otherwise start a new output interval. Touching endpoints are merged under this contract.

## Why it matters

Sorting dominates at O(n log n); the merge scan is O(n). Copy interval values into the output so the algorithm does not unexpectedly mutate the caller’s nested arrays. If the domain uses half-open time ranges, revisit the boundary comparison.

## A practical example

```js
function mergeIntervals(intervals) {
  const sorted = intervals.map(([a, b]) => [a, b]).sort((a, b) => a[0] - b[0]);
  const result = [];
  for (const [start, end] of sorted) {
    const last = result[result.length - 1];
    if (!last || start > last[1]) result.push([start, end]);
    else last[1] = Math.max(last[1], end);
  }
  return result;
}
// Input contract: each closed interval has start <= end.
```

## Common mistakes

Do not update the merged end to the next end unconditionally; a contained interval can otherwise shorten the merged range.

## The idea

Component contracts should express valid UI configurations. A discriminated union can require an onChange callback for a controlled input and forbid a conflicting defaultValue. Generics can preserve the relationship between list items and render callbacks.

## Why it matters

Derive native props with ComponentPropsWithoutRef when wrapping a real element. Use Omit to resolve deliberate prop conflicts and preserve accessibility-related props. Avoid broad assertions around generic callbacks. Stable keys remain a runtime identity concern even with well-typed item objects.

## A practical example

```tsx
import type { ReactNode } from "react";
type InputMode =
  | { value: string; onChange: (value: string) => void; defaultValue?: never }
  | { defaultValue?: string; value?: never; onChange?: never };

type ListProps<T> = {
  items: readonly T[];
  getKey: (item: T) => string;
  renderItem: (item: T) => ReactNode;
};
function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return <ul>{items.map(item =>
    <li key={getKey(item)}>{renderItem(item)}</li>
  )}</ul>;
}
```

## Common mistakes

Optional callbacks combined with an always-present value can leave a controlled input unable to update. Do not make every component polymorphic just because the type system can express it. Preserve native semantics and forward relevant props.

## Try it yourself

Use List with notes and with users; verify renderItem infers the correct item. Add a compile-time negative example that supplies both value and defaultValue to InputMode.

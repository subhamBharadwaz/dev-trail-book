## The idea

In the App Router, a Server Component can load server-side data and compose UI without shipping its component implementation as browser JavaScript. A Client Component supplies interactivity and browser hooks. The use client directive defines a module boundary; it is not a command to fetch all data in the browser.

## Why it matters

Keep secrets and privileged data access on the server. Pass an intentionally small, serializable view model into an interactive component. Client Components can contribute to server-generated initial HTML, so client does not mean that no server rendering is involved.

## A practical example

```ts
// app/journal/page.tsx — Server Component
import { getEntriesForCurrentUser } from "@/data/entries";
import { EntryFilter } from "./entry-filter";
export default async function JournalPage() {
  const entries = await getEntriesForCurrentUser();
  return <EntryFilter entries={entries.map(entry => ({
    id: entry.id, title: entry.title,
  }))} />;
}
// entry-filter.tsx begins with 'use client' and owns filter state.
```

## Common mistakes

Marking a large subtree use client can unnecessarily expand the client bundle. Start with the smallest interactive boundary that meets the requirement.

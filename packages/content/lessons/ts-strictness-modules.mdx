## The idea

Strict checking makes assumptions visible before runtime. strictNullChecks distinguishes null and undefined from present values. noUncheckedIndexedAccess adds undefined to unchecked indexed reads; exactOptionalPropertyTypes distinguishes an absent optional property from explicitly assigning undefined when it is not part of the declared value type.

## Why it matters

The strict umbrella does not enable every safety option. Introduce extra flags gradually and fix causes rather than adding non-null assertions. Use import type for type-only dependencies and choose module settings that match the bundler or runtime. In a monorepo, consumers need a deliberate package export contract; a path alias alone does not configure every runtime.

## A practical example

```ts
type Preferences = { theme?: "light" | "dark" };
const values: string[] = [];
const first = values[0]; // string | undefined with noUncheckedIndexedAccess
if (first !== undefined) console.log(first.toUpperCase());

// tsconfig.json options for a gradual safety pass:
// "strict": true,
// "noUncheckedIndexedAccess": true,
// "exactOptionalPropertyTypes": true
// With exactOptionalPropertyTypes, { theme: undefined } is rejected
// unless undefined is explicitly included in the property's type.
```

## Common mistakes

Non-null ! assertions are erased and can hide a missing array element. Do not copy Node module resolution settings into a Vite app blindly. Run the actual app and package typechecks, not an empty solution config.

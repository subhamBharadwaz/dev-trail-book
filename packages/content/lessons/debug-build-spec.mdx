## The idea

Start a build-from-spec task by restating the user goal, required states, inputs, and constraints. Identify the smallest coherent implementation before adding optional polish. For debugging, reproduce the issue and isolate the first incorrect assumption rather than rewriting the entire feature.

## Why it matters

Use the same task loop for a filterable list, async form, or search box: enumerate happy and failure states, implement a small vertical slice, test it, then improve readability. In an interview, explain trade-offs and what remains unverified.

## A practical example

```js
const acceptance = [
  "The input has an accessible label",
  "Filtering is case-insensitive",
  "No matches has a useful empty state",
  "A failed request can be retried",
  "An obsolete response cannot replace newer results",
];
// Build and verify one complete interaction before optional features.
```

## Common mistakes

Do not spend the whole time on setup or visual polish while the required interaction remains incomplete.

## Try it yourself

Build a responsive user search in 60–90 minutes. Reserve the final ten minutes for failure cases, keyboard checks, and a short handoff.

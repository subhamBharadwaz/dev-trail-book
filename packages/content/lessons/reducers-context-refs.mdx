## The idea

A reducer describes state transitions with actions. Context distributes a value through a subtree. A ref stores a mutable value whose changes do not trigger rendering. These tools solve different problems and can be composed without putting every value into global state.

## Why it matters

Keep transient input state close to its input. Share reading progress when several views need it. Use refs for DOM nodes, timer handles, or other imperative resources. A context provider changing its value can update consumers; context is not automatically a performance optimization.

## A practical example

```tsx
function reducer(state, action) {
  switch (action.type) {
    case "saved":
      return { ...state, saved: [...state.saved, action.id] };
    case "cleared":
      return { ...state, saved: [] };
    default:
      return state;
  }
}
const [state, dispatch] = useReducer(reducer, { saved: [] });
// dispatch({ type: "saved", id: "closures" });
```

## Common mistakes

Do not move all state into context simply to avoid passing one prop. Wider ownership creates more coupling.

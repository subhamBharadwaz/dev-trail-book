## The idea

Structured model output is useful when the application needs a predictable object rather than free-form prose. Define the contract, request it through a supported server integration, parse the response, and validate the result before using it.

## Why it matters

Handle malformed JSON, a schema mismatch, refusal, timeout, and missing required content as deliberate outcomes. A TypeScript interface or a JSON.parse call is not sufficient validation. Keep the exercise small: one schema and one feature, rather than a new platform.

## A practical example

```ts
type Summary = { title: string; facts: string[] };
function isSummary(value: unknown): value is Summary {
  if (typeof value !== "object" || value === null) return false;
  return (
    "title" in value &&
    typeof value.title === "string" &&
    "facts" in value &&
    Array.isArray(value.facts) &&
    value.facts.every((item) => typeof item === "string")
  );
}
const parsed: unknown = JSON.parse(rawModelText);
if (!isSummary(parsed)) throw new Error("Unexpected summary format");
// Add length limits and business constraints at the same boundary.
```

## Common mistakes

Do not repair arbitrary invalid output with silent coercions that change its meaning. Decide what the application may safely accept.

## Try it yourself

Test missing facts, a number in the facts array, malformed JSON, and an unexpectedly long title. Keep invalid data out of the rendered feature.

## Keep exploring

Read the [technical reference](https://json-schema.org/understanding-json-schema) for the full contract and check behavior against your project version.


## Validation failure matrix

Test invalid JSON, null, an array instead of an object, missing title, non-string title, a facts value that is not an array, one non-string fact, excessive title length, excessive fact count and business-invalid content. Define these limits in a server-side schema and reject before rendering or storing. Validate the complete result after streaming finishes; partial JSON is not a final object. Report refusal separately where the provider protocol supports it. Bound repair retries and preserve a safe failure state.

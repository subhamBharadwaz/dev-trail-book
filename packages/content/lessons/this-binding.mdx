## The idea

For an ordinary function, this depends on the call site. obj.method() provides obj as the receiver; extracting method and calling it separately loses that receiver. Arrow functions capture this from their surrounding lexical context rather than receiving a new one.

## Why it matters

Class syntax does not automatically bind every method. When passing methods as callbacks, decide whether to bind once, wrap the call, or use an appropriate arrow function. In strict-mode functions and ES modules, an unbound ordinary call has undefined as this.

## A practical example

```js
const account = {
  name: "Trailbook",
  describe() {
    return this.name;
  },
};
console.log(account.describe()); // Trailbook
const bound = account.describe.bind(account);
console.log(bound()); // Trailbook
// account.describe.call({ name: "Notes" }) => Notes
```

## Common mistakes

Do not choose arrows just to make every this problem disappear. An arrow stored as an object property does not automatically capture that object.

## Try it yourself

Extract describe into a variable, call it, then repair the call with bind. Explain the difference without changing the object.

## Call-site debugging drill

```ts
const person = {
  name: "Ada",
  say() {
    return this.name;
  },
};
const detached = person.say;
const bound = person.say.bind(person);
console.log(bound()); // Ada
console.log(detached.call({ name: "Lin" })); // Lin
console.log(person.say.apply({ name: "Sam" }, [])); // Sam
```

A regular function receives this according to how it is called. A detached strict-mode call has undefined this; reading this.name then throws. bind creates a function with a fixed receiver; call invokes with individual arguments, apply with an argument list. An arrow captures lexical this and cannot be rebound by call/apply/bind. Constructor new establishes its own receiver for constructible regular functions. A method passed directly as an event callback loses the original property-call receiver.

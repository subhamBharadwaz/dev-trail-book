## The idea

Objects can delegate property lookup to a prototype. If a property is absent on the object, lookup continues through that chain. Class methods are normally shared through the prototype; instance fields belong to each instance. JavaScript classes use this object model rather than introducing an unrelated inheritance mechanism.

## Why it matters

Check whether behavior belongs to each instance or can be shared. Favor composition when inheritance obscures ownership. Being able to explain own properties versus inherited properties is more useful than memorizing the spelling of class syntax.

## A practical example

```js
class Counter {
  value = 0;
  increment() {
    this.value += 1;
  }
}
const a = new Counter();
const b = new Counter();
a.increment();
console.log(a.value, b.value); // 1, 0
console.log(a.increment === b.increment); // true
console.log(Object.hasOwn(a, "value")); // true
```

## Common mistakes

Do not mutate built-in prototypes to solve local application problems. It can unexpectedly affect unrelated code.

## Try it yourself

Add a getter to Counter, inspect its prototype, and compare it with an arrow function stored as an instance field.

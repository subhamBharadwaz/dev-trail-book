## The idea

A stack is useful when the next event must resolve the most recent unmatched event. For bracket validation, each opener adds an expected closer. A closer must match the top expectation. The input is valid only if every character is accepted and the stack is empty at the end.

## Why it matters

State the accepted input alphabet. The example rejects characters other than brackets. It scans once in O(n) time and can use O(n) extra space for nested input. The same last-in-first-out reasoning appears in parsing and iterative depth-first traversal.

## A practical example

```js
function validBrackets(text) {
  const closing = { "(": ")", "[": "]", "{": "}" };
  const stack = [];
  for (const char of text) {
    if (Object.hasOwn(closing, char)) stack.push(closing[char]);
    else if (![")", "]", "}"].includes(char) || stack.pop() !== char) {
      return false;
    }
  }
  return stack.length === 0;
}
```

## Common mistakes

Do not accept a sequence merely because no mismatch was seen yet; unfinished openings must also be rejected.

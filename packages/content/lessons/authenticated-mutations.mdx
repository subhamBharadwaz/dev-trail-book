## The idea

A reliable mutation crosses several boundaries: identify the caller, validate the request, authorize access to the target, perform the write, and return a safe result. Keep those checks close enough to the actual write that another transport cannot bypass them.

## Why it matters

Use a constrained update that includes the owner or tenant condition. Check its affected-row count. Apply transactions when several writes must succeed or fail together. Log internal diagnostics separately from the safe message returned to a user.

## A practical example

```ts
async function renameEntry(userId, entryId, rawTitle) {
  if (typeof rawTitle !== "string" || !rawTitle.trim()) {
    return { ok: false, error: "A title is required" };
  }
  const title = rawTitle.trim();
  if (title.length > 200) return { ok: false, error: "Title is too long" };
  const result = await db.entries.updateMany({
    where: { id: entryId, ownerId: userId },
    data: { title },
  });
  if (result.count !== 1) return { ok: false, error: "Entry unavailable" };
  return { ok: true };
}
```

## Common mistakes

A read-then-write sequence without a consistent authorization condition can allow stale assumptions. Put the access restriction on the write.

## Try it yourself

Exercise invalid input, a missing record, another user’s record, a database failure, and a successful rename.

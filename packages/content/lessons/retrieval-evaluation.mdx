## The idea

Retrieval selects relevant source material for an answer. A useful citation identifies a source that actually supports the associated claim. When the retrieved material does not support an answer, the feature needs an explicit unsupported-answer response rather than invented certainty.

## Why it matters

The plan makes this optional and deliberately small. Use a tiny document set, stable source identifiers, access controls, and ten representative test cases. Include absent facts, conflicting information, misleading instructions inside documents, and irrelevant retrieval, not just easy successful questions.

## A practical example

    expected: "14 days, cite policy-v1",
  },
  {
    question: "Do digital purchases qualify?",
    sources: ["policy-v2"],

## Common mistakes

Do not turn the optional exercise into a large new RAG capstone. The plan explicitly protects time for core skills and applications.

## Try it yourself

Create ten concrete questions against two short documents. Check source support and unsupported-answer behavior manually before adding complexity.

## Keep exploring

Read the [technical reference](https://www.nist.gov/itl/ai-risk-management-framework) for the full contract and check behavior against your project version.


## Evaluation rubric

Run every fixture against a fixed corpus and caller permissions. Inspect the exact supporting passage, claim accuracy, citation identity, access filtering and abstention. Record pass/fail and a short reason for each dimension; a citation that points to a real document but does not support the claim still fails. The embedded-command fixture should also be repeated with hostile text placed inside a retrieved document. These are test fixtures, not evidence that a model already passed.

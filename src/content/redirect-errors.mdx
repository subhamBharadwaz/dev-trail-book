## The idea

Next.js redirect() ends the current control flow by throwing a framework redirect signal. A surrounding catch can intercept that signal and report a failure even after the database save succeeded. That is why the redirect belongs after a mutation try/catch whose failure branch returns.

## Why it matters

Finally is also the wrong success-only location: it runs after both success and failure. Keep save errors inside the catch and put navigation on the path reached only after success. The helper names in this example represent your application’s validated, authorized server layer.

## A practical example

```ts
"use server";
import { redirect } from "next/navigation";
export async function saveJournal(formData: FormData) {
  const user = await requireUser();
  const input = parseEntry(formData);
  if (!input.ok) return { error: "Check the entry fields" };
  try {
    await saveEntryForUser(user.id, input.value);
  } catch {
    return { error: "Could not save entry" };
  }
  redirect("/journal");
}
```

## Common mistakes

The misconception was that redirect avoids catch automatically. It does not: the redirect signal is thrown. Moving it outside the caught region preserves the intended control flow.

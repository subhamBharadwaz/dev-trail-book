## The idea

Choose elements by meaning: buttons perform actions, links navigate, headings describe structure, and labels name form fields. CSS then controls presentation. The box model distinguishes content, padding, borders, and margins; box-sizing changes how declared dimensions include those pieces.

## Why it matters

Use Flexbox for arranging items along one primary axis and Grid for relationships across rows and columns. Start with a narrow layout, allow content to wrap, and add breakpoints when the content needs more room. Test zoom and long text as well as device widths.

## A practical example

```tsx
<main className="mx-auto max-w-5xl px-4 py-8">
  <h1 className="text-3xl font-semibold">Your notes</h1>
  <section
    aria-label="Topic collections"
    className="mt-6 grid gap-4 sm:grid-cols-2 lg:grid-cols-3"
  >
    <a
      href="/topics/react"
      className="rounded-xl border p-5
      focus-visible:outline-2 focus-visible:outline-offset-4"
    >
      <h2 className="text-lg font-medium">React</h2>
      <p className="mt-2 text-sm">Components and state.</p>
    </a>
  </section>
</main>
```

## Common mistakes

Do not hide essential actions on mobile just to make a screenshot fit. Reorganize the layout while keeping the task available.

## Try it yourself

Implement the same filterable list at narrow, medium, and wide widths. Test a very long topic title and 200% zoom.

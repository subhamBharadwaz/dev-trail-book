## The idea

A Server Action is a server function integrated with React-driven mutations. A Route Handler implements an HTTP endpoint with an explicit method, request, and response. Both cross a trust boundary and require input validation and access checks.

## Why it matters

Use an Action for an app form when that integration fits. Use a Route Handler for webhooks, external clients, or an HTTP contract you intend to expose. Do not duplicate the business rules in both; keep validation and mutation logic in a shared server layer.

## A practical example

```ts
// app/api/entries/route.ts — illustrative server helpers
export async function POST(request: Request) {
  const user = await requireUser();
  const input = await request.json().catch(() => null);
  const parsed = entrySchema.safeParse(input);
  if (!parsed.success) {
    return Response.json({ error: "Invalid entry" }, { status: 400 });
  }
  const entry = await createEntryForUser(user.id, parsed.data);
  return Response.json({ id: entry.id }, { status: 201 });
}
```

## Common mistakes

Do not assume a hidden button protects a server function. The permission check must run at the actual data or mutation boundary.

## Try it yourself

Model one create-entry operation as a form Action and as an HTTP handler. Keep one shared authorization and mutation function.

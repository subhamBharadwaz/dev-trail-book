## The idea

Each render creates a snapshot of state and the functions that refer to it. A delayed callback retains the bindings from the render that created it. This is ordinary closure behavior, not React randomly losing an update.

## Why it matters

Use a functional state updater when the next value depends on the previous value. When synchronizing external systems, declare the reactive dependencies used by the Effect. A ref can hold a mutable value, but using one to hide dependencies can conceal a synchronization bug.

## A practical example

```tsx
import { useState } from "react";
export function DelayedCounter() {
  const [count, setCount] = useState(0);
  function addLater() {
    setTimeout(() => setCount((current) => current + 1), 300);
  }
  return <button onClick={addLater}>{count}</button>;
}
```

## Common mistakes

Using a mutable ref for everything removes useful render-time state. Decide whether a value belongs to the UI snapshot or to an external mutable resource.

## Try it yourself

Click the delayed counter five times quickly. Compare count + 1 with current =&gt; current + 1 and explain the result.

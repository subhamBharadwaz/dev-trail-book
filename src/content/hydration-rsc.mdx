## The idea

HTML provides an initial document. Hydration connects browser-side React behavior to compatible pre-rendered markup. The RSC payload describes rendered Server Component output and references needed to compose it with Client Components. These are related parts of an experience, not three names for the same response.

## Why it matters

The initial browser render must match the pre-rendered markup closely enough for hydration. Reading a browser-only value while generating the initial render can create a mismatch. Prefer stable initial output and synchronize browser-specific values after the boundary is ready.

## A practical example

```tsx
"use client";
import { useEffect, useState } from "react";
export function LocalTime() {
  const [time, setTime] = useState<string | null>(null);
  useEffect(() => setTime(new Date().toLocaleTimeString()), []);
  return <span>{time ?? "Local time loads after hydration"}</span>;
}
```

## Common mistakes

Do not describe every Server Component update as hydration. Server output and interactive client behavior have different responsibilities.

## Try it yourself

Cause a mismatch with a random value, then replace it with a stable server-provided value or an intentional client-only update.

## The idea

XSS executes attacker-controlled content in a trusted page. CSRF abuses a browser’s ambient credentials to request unwanted actions. SQL injection changes query meaning through unsafe input construction. CORS is a browser cross-origin access mechanism; it does not authorize every client of an API.

## Why it matters

Use safe rendering and context-appropriate encoding, framework-compatible CSRF protections, parameterized database queries, server-side access checks, and secrets kept outside client bundles. Rate limiting reduces abuse pressure but is not a substitute for any of those controls.

## A practical example

```ts
// Parameter binding keeps user input out of SQL syntax.
const result = await client.query(
  "SELECT id, title FROM entries WHERE owner_id = $1 AND title = $2",
  [user.id, title],
);
// Do not build SQL by concatenating title into the query text.
// Do not expose private API keys through VITE_ or public client props.
```

## Common mistakes

Do not claim one setting such as HttpOnly, CORS, or HTTPS solves all web-security problems. Each protects a different boundary.

## Try it yourself

Map one authenticated form against XSS, CSRF, SQL injection, leaked secrets, and repeated requests. Explain the specific control for each threat.
